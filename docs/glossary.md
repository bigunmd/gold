# GOLD project glossary

Shared vocabulary for GOLD's engineering guidance and host integrations.

| Term | Definition | Distinction |
|---|---|---|
| GOLD core | Shared engineering policy, scenario routing, role guidance and reusable skill resources. | Does not supply a runtime, model or permission enforcement. |
| Host adapter | Binding of GOLD's shared guidance to a host's startup instructions, skill discovery and available capabilities. | Not a fork of the engineering policy or a replacement coding agent. |
| Preset | A selectable DSH entry point combining GOLD guidance with the configured runtime tools. | A role's initial focus is not a sandbox or an authorization grant. |
| Skill | An on-demand instruction entry point with its supporting resources. | Installing skills alone does not activate GOLD's startup routing. |
| User-only skill | A skill intended for explicit human invocation, not automatic selection or indirect loading by another skill. | Human invocation does not approve all possible side effects. |
| Managed block | The installer-owned GOLD section of a project's host instruction document. | Surrounding project instructions remain independently owned. |
| Installation manifest | The record of a project-local adapter's host, version, content identity and managed resource hashes. | Not a task-state record or proof of live host compliance. |
| Current architecture view | Authoritative description for a stated scope and verified source baseline or deployment environment. | Current source structure does not prove production deployment; target designs are not current facts. |
| Use-case view | Focused description of how established architecture elements interact in a meaningful scenario. | A behavioral view, not an additional C4 structural level; proposed interactions belong with evolution. |
| Evolution proposal | Shared description of a consequential architectural target and transition, with explicit lifecycle status and provenance. | Not current architecture, an execution log, or permission to implement; closed proposals remain historical. |
| Delivery acceptance | Explicit human acceptance of current verification evidence for the approved scope. | A review verdict, passing tests or completed implementation alone is not acceptance. |
