## GOLD adaptations

All eight resources replace Claude-specific tools/model settings, unavailable context-manager JSON protocols, automatic cross-agent integration and canned numeric achievements. Domain targets are project-specific, not copied success claims. Mutations, active tests and external communication require actual authorization. Every resource states required context, evidence, output and stop conditions and links the existing GOLD scenario method.

Accessibility guidance explicitly selects the applicable standard/version/level; it does not treat WCAG versions as interchangeable or claim legal certification. Security findings do not imply complete vulnerability coverage. Incident urgency grants no emergency permission. Git policy distinguishes human attribution, legal notices and required disclosures from prohibited model authorship.

The full upstream MIT notice is retained in [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md) and required in runtime packages. GOLD's own [LICENSE](../../LICENSE) remains separate.

## Updating an adaptation

Pin the proposed upstream revision, inspect the actual source/license diff, document meaningful changes and review new runtime assumptions or notices. Update bounded resources and positive/missing-evidence/overreach scenarios, run package/resource checks and independent review. Never bulk-install or automatically synchronize upstream prompts. Upstream role claims are not evidence of model expertise or compliance.
